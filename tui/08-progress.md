# 08 · TUI progress report

**Status:** Experimental implementation in progress. Release 1A is incomplete; the remaining releases are planned. This report describes source behavior and local checks, not a release or deployment.

## Implemented

- `darkubectl tui` launches an alternate-screen browser. It requires terminal input and output. Live mode is read-only unless `--allow-writes` is explicitly set, and resolves a tenant from flags/config or the inline sidebar selector; fixture mode uses only local YAML and needs neither. The command rejects positional arguments and non-table output. Help is available without a terminal.
- Live mode resolves configuration and authentication through the existing client adapters. It loads account Profile for discovery and lists apps through a tenant-scoped `Client.ListApps`. Fixture mode branches before config/auth resolution and client construction, and renders only the mock profile's apps. Neither mode offers app writes or secret-reveal actions.
- Live mode loads account Profile independently of Apps. With no tenant, the sidebar offers Profile memberships; if Profile fails, it offers local config slugs. A configured tenant remains usable if Profile fails, and is marked unverified if Profile succeeds without that tenant. Focus the Tenant pane with `1`; moving the highlight switches tenant immediately and clears prior app data before loading the new scope. No `t` shortcut or Enter confirmation is used.
- `n` opens a fuzzy namespace picker. It lazily loads complete inventory through `Client.ListNamespaces`, keeps distinct namespace IDs, shows per-namespace app counts including empty projects, and scopes the Apps tree without a second app request. If inventory is unavailable, it falls back to namespaces in the loaded app snapshot and labels the omission of empty projects. Mock files may include tenant-specific `namespaces` for offline previews of empty projects.
- `a` opens a contextual app lifecycle menu. Live writes require `--allow-writes`; Restart always has a Yes/No confirmation, and Delete requires typing the exact app name before clicking a separate Delete app button (or using Tab/Enter). Both actions re-fetch the app by UUID and verify its name before dispatch. Mock mode simulates Restart without changing data and removes a deleted app only from the current session; it makes no API call and leaves the fixture file untouched. App Stop is omitted because there is no distinct app-stop command.
- The browser has four panes across three columns: equal-height Tenant and Pages panes in a narrow left navigation rail, then Apps and the selected-item detail workspace. Pane headings show `[1]` through `[4]` to match their focus shortcuts. Tenant always lists available tenants, scrolling the list when it exceeds the pane height. Apps is the only active global page; Activity, Tickets, Resources, Registry, Billing and Account are disabled placeholders. Summary and Usage are implemented app-specific views; Pods, Logs, Builds, Env, Terminal and Domains remain planned. `[` / `]` switches between Summary and Usage. `1`/`2`/`3`/`4` focuses Tenant, Pages, Apps and Details; Tab/Shift+Tab cycles through them. The header shows a tenant breadcrumb, adding namespace and app in app context, with a pulsing blue live marker that becomes an animated spinner during Profile or Apps requests; mock mode retains an offline marker.
- `/` opens an inline app filter after the breadcrumb. It applies case-insensitive fuzzy subsequence matching as text is entered; `namespace/appname` scopes both fields, while an app-only query searches all namespaces. Up/Down moves through filtered rows without a commit step; Enter opens the selected match, and Esc cancels editing or clears the query.
- `--mock-file PATH` loads a strict version-1 YAML fixture, with either one tenant or multiple tenant-specific app snapshots. Unknown fields and multiple documents are rejected; input is capped at 1 MiB and 1000 total apps. Parser errors omit YAML snippets. The browser labels the source `MOCK PROFILE · OFFLINE`; `demo/mock-profile.yaml` contains two fictional tenants for exercising session-only tenant switching.
- Apps are grouped by namespace with tree connectors and per-namespace app counts (counts reflect current filter matches). Namespace rows can be collapsed or expanded with Enter or Left/Right and `h`/`l`; Up/Down and `j`/`k` move through visible rows. Home/End and `g`/`G` jump to the first/last visible row.
- `s` opens sort selection for name, namespace, state, and last updated. Up/Down selects a field and Left/Right sets ascending or descending order. Sorting preserves the selected app ID.
- Apps and Summary remain visible beside the left navigation rail. Up/Down moves the selected app and updates its summary from the loaded snapshot. The summary heading includes the app name; CPU, RAM, and applicable disk usage appear indented under Plan with icons. When usage samples are unavailable, show the configured total without a fabricated used value. Timestamps render in local time, and creation methods use an icon with a short label. Summary shows only the primary Port Service, not the full port map; the future app Ports view can show every mapping. Internal Address has its own row and includes the chosen service port when unambiguous. External IP shows `-` when no service object or IP is returned. ClusterIP/internal-only services commonly have no external IP; a LoadBalancer IP may also be absent until the API returns one. Readiness probe, command, and input names render only when returned. Domains combines the custom domain, external host list, and service external address, with case-insensitive deduplication and OSC 8 links; multiple hosts use separate aligned rows. Input values are not retained or displayed. Right/`l` or Enter on an app focuses Summary and fetches the typed app by UUID; Left/`h` from Summary returns to the tree. On a namespace row, Left/`h` collapses and Right/`l` expands it. The contextual key hints stay pinned to the bottom row.
- Focusing Summary refreshes its typed app by ID in live mode, while fixture mode uses its local app snapshot. The summary shows tenant, namespace/cluster, ID, state and description, desired replicas, plan/resources, creation method, image, domains, and update time. `r` refreshes the focused view. Failed detail reads retain the last known data and show an error; a successful 404 remains a detail error and never resolves by name.
- Each async dataset (Profile, Apps, namespace inventory, Summary detail, and Usage) has an independent request state and request/scope stamp. Loads receive cancellable request contexts. Tenant switches and selected-app changes cancel obsolete reads; monotonically increasing request IDs and scope generations reject late results even if cancellation races. Same-scope refresh failures keep the prior snapshot and show a stale marker, last-success time, and retry guidance. Namespace fallback is marked Partial, and Usage errors do not fail Summary detail.
- Manual list refresh preserves the selected app ID when possible, and keeps old rows with a stale warning when the refresh fails. The UI has a centered shortcut-help modal over the app browser, terminal size prompt, cell-aware app-name alignment, status glyphs, colors, and reverse-video selection. `NO_COLOR` disables foreground colors.
- Footer and help use a shared state-aware key-hint registry with responsive width fitting. Enter is shown with `↵`; vim and arrow alternatives are listed where they work. Help and sort overlays consume their own keys; actions are unavailable while a namespace row is selected. The Apps tree supports PageUp/PageDown, and the selected-row highlight uses shared semantic palette tokens across the tree, context rail and action controls. The mock header clearly says `MOCK PROFILE · OFFLINE`.
- MCP classifies `tui` as blocked, including when writes are enabled.

## Remaining for release 1A

- **1A-C1 through 1A-C5 implementation is complete.** C1 covers keyboard/style consistency and navigation. C2 covers request lifecycle and stale-result rejection. C3 covers typed Summary semantics and API-shaped fields. C4 covers terminal lifecycle, resize-state preservation, and long-session auth. C5 restricts writes to confirmed Restart/Delete, verifies mock isolation and the MCP block, and reconciles the docs. Release 1A still needs final interactive mock acceptance at minimum, normal, and wide terminal sizes, plus an authorized live read-only check if credentials are available.
- Live credential renewal and destructive live actions were not exercised. The mock was exercised in a PTY for normal quit and Ctrl+C; interactive PTY resize was unavailable.
