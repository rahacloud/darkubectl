# 08 · TUI progress report

**Status:** Experimental implementation in progress. Release 1A is incomplete; the remaining releases are planned. This report describes source behavior and local checks, not a release or deployment.

## Implemented

- `darkubectl tui` launches an alternate-screen browser. It requires terminal input and output. Live mode is read-only unless `--allow-writes` is explicitly set, and resolves a tenant from flags/config or the inline sidebar selector; fixture mode uses only local YAML and needs neither. The command rejects positional arguments and non-table output. Help is available without a terminal.
- Live mode resolves configuration and authentication through the existing client adapters. It loads account Profile for discovery and lists apps through a tenant-scoped `Client.ListApps`. Fixture mode branches before config/auth resolution and client construction, and renders only the mock profile's apps. Live app writes require `--allow-writes` and confirmation; secret values are hidden initially and can be revealed or copied for the selected row.
- Live mode loads account Profile independently of Apps. With no tenant, the sidebar offers Profile memberships; if Profile fails, it offers local config slugs. A configured tenant remains usable if Profile fails, and is marked unverified if Profile succeeds without that tenant. Focus the Tenant pane with `1`; moving the highlight switches tenant immediately and clears prior app data before loading the new scope. No `t` shortcut or Enter confirmation is used.
- `n` opens a fuzzy namespace picker. It lazily loads complete inventory through `Client.ListNamespaces`, keeps distinct namespace IDs, shows per-namespace app counts including empty projects, and scopes the Apps tree without a second app request. If inventory is unavailable, it falls back to namespaces in the loaded app snapshot and labels the omission of empty projects. Mock files may include tenant-specific `namespaces` for offline previews of empty projects.
- `a` opens a contextual app lifecycle menu. Live writes require `--allow-writes`; Restart always has a Yes/No confirmation, and Delete requires typing the exact app name before clicking a separate Delete app button (or using Tab/Enter). Both actions re-fetch the app by UUID and verify its name before dispatch. Mock mode simulates Restart without changing data and removes a deleted app only from the current session; it makes no API call and leaves the fixture file untouched. App Stop is omitted because there is no distinct app-stop command.
- The browser has four panes across three columns: equal-height Tenant and Pages panes in a narrow left navigation rail, then the selected page list and details. Pane headings show `[1]` through `[4]` to match their focus shortcuts. Apps, Activity, Tickets, DB and Registry are Pages entries. DB loads tenant managed databases through `get databases`, shows engine/version, instance and per-node status and capacity, and supports local filtering, sorting and manual refresh. Selecting a DB fetches connection details and shows external/internal endpoints together. The DBaaS API returns a Vault path in its password field; the TUI points to the database's Console URL for TOTP protected password retrieval and never places that path into copied URIs. Mock connections are synthetic. It remains read only. Summary includes the selected app namespace's effective Outbound IP from authenticated `GET /ip-management/api/egress-route/` data and a pod/container snapshot. Summary, Resources, Logs and Env are app-specific views. Resources combines editable configuration with current measurements and history; writes stage changes for diff review and read-back verification. Logs reads selected pod/container output, supports follow, previous logs, search, copy and maximize. Env shows plain values, masks secrets initially, reveals the selected secret with `v`, and copies the selected value with `y`. Write mode stages multiple Env edits, marks changed rows, and reviews a diff before one confirmed save. Terminal is first in the app action menu, selects a pod/container, suspends the browser for a remote PTY, passes keystrokes and paste through, sends terminal size changes, and prints control guidance to stdout. `[` / `]` switches views. `1`/`2`/`3`/`4` focuses Tenant, Pages, list and Details; Tab/Shift+Tab cycles through them.
- `/` opens an inline app filter after the breadcrumb. It applies case-insensitive fuzzy subsequence matching as text is entered; `namespace/appname` scopes both fields, while an app-only query searches all namespaces. Up/Down moves through filtered rows without a commit step; Enter opens the selected match, and Esc cancels editing or clears the query.
- `--mock-file PATH` loads a strict version-1 YAML fixture, with either one tenant or multiple tenant-specific app snapshots. Unknown fields and multiple documents are rejected; input is capped at 1 MiB and 1000 total apps. Parser errors omit YAML snippets. The browser labels the source `MOCK PROFILE · OFFLINE`; `demo/mock-profile.yaml` contains two fictional tenants, plain and secret Env examples, and pod/container targets. Mock Env edits stay in memory for the current session; secret values are generated placeholders and never stored in the fixture.
- Apps are grouped by namespace with tree connectors and per-namespace app counts (counts reflect current filter matches). Namespace rows can be collapsed or expanded with Enter or Left/Right and `h`/`l`; Up/Down and `j`/`k` move through visible rows. Home/End and `g`/`G` jump to the first/last visible row.
- `s` opens sort selection for name, namespace, state, and last updated. Up/Down selects a field and Left/Right sets ascending or descending order. Sorting preserves the selected app ID.
- Apps and Summary remain visible beside the left navigation rail. Up/Down moves the selected app and updates its summary from the loaded snapshot. Summary groups fields under Identity, Status, Resources, Networking, Runtime, Deployment and Pods; the app name appears once as a labeled Name row under Identity. CPU, RAM and Disk show configured totals with glyphs and `-` for missing values; current measurements and history are shown in Resources. The Pods group contains a snapshot of pod and container readiness, status, restart counts, age and previous state. Timestamps render in local time, and creation methods use an icon with a short label. Summary shows only the primary Port Service, not the full port map; Internal Address includes the chosen service port when unambiguous. Missing service values render as `-`. Domains combines the custom domain, external host list, and service external address, with case-insensitive deduplication and OSC 8 links; multiple hosts use separate aligned rows. Input values are not retained or displayed. Resources shows plan, CPU/RAM, disk, replica and HPA configuration alongside live usage and charts. PgUp/PgDn scrolls Summary and Resources while keeping the tabs and active view title visible; Summary also keeps Identity and Name visible. Right/`l` or Enter on an app focuses Summary and fetches the typed app by UUID; Left/`h` from Summary returns to the tree. On a namespace row, Left/`h` collapses and Right/`l` expands it. The contextual key hints stay pinned to the bottom row.
- Focusing Summary refreshes its typed app by ID in live mode, while fixture mode uses its local app snapshot. The summary shows tenant, namespace/cluster, ID, state and description, desired replicas, plan/resources, creation method, image, deployment type (`↻` Darkube for `webhook`, `⚙` Custom CI/CD for `gitlabci`), domains, and update time. Unknown methods remain Unknown; deploy-token presence is not used because it appears on both deployment modes. `r` refreshes the focused view. Failed detail reads retain the last known data and show an error; a successful 404 remains a detail error and never resolves by name.
- Env is wired into the app detail view. Plain values are visible, secrets can be revealed per selected row with `v`, and `y` copies either selected value. `e` edits a value, `+` adds plain, `A` adds secret, and `d` stages deletion. `s` reviews the batch diff before one confirmed save; `x` discards staged changes. Terminal is first in the app action menu and lets the user select a pod/container, suspends the browser for the remote PTY, passes raw keys and paste through, and prints the selected target and Ctrl+D/Ctrl+C/Ctrl+L help to stdout. Mock mode previews the target without connecting or executing commands. Automated and interactive acceptance have not yet been run.
- Each async dataset (Profile, Apps, namespace inventory, Summary detail, Usage, Egress Routes, pod snapshots and Logs) has an independent request state and request/scope stamp. Loads receive cancellable request contexts. Tenant switches, selected-app changes, and leaving Logs cancel obsolete reads; monotonically increasing request IDs and scope generations reject late results even if cancellation races. Same-scope refresh failures keep the prior snapshot and show a stale marker, last-success time, and retry guidance. Namespace fallback is marked Partial, and Usage errors do not fail Summary detail. Log polling waits for each request to finish, backs off after errors, and preserves the buffer when scrolled away from the bottom.
- Manual list refresh preserves the selected app ID when possible, and keeps old rows with a stale warning when the refresh fails. The UI has a centered shortcut-help modal over the app browser, terminal size prompt, cell-aware app-name alignment, status glyphs, colors, and reverse-video selection. `NO_COLOR` disables foreground colors.
- Footer and help use a shared state-aware key-hint registry with responsive width fitting. Enter is shown with `↵`; vim and arrow alternatives are listed where they work. Help and sort overlays consume their own keys; actions are unavailable while a namespace row is selected. The Apps tree supports PageUp/PageDown, and the selected-row highlight uses shared semantic palette tokens across the tree, context rail and action controls. The mock header clearly says `MOCK PROFILE · OFFLINE`.
- Builds is available as pane 4's view after Logs and before Env. Git repository apps load the latest 30 builds, preserve selection by build ID on refresh, open build output by Enter or a second click, and support output scrolling, literal search, match navigation and clipboard copy. Unsupported app types and unknown eligibility are explained without issuing build-list requests. Build output is control-stripped, capped at 2 MiB and marked when truncated; errors are bounded and only recognized string forms are shown. The offline fixture simulates build list, output, latest-build, retry and stop actions in memory. Live write actions require `--allow-writes`, confirm the app/build target, and recheck app eligibility, build ownership and running status immediately before retry/stop. Submission acceptance and later build-state observations are reported separately; no live write has been sent.
- Domains follows Env and shows custom host DNS checks, platform-issued certificate expiry, ingress CNAME, DNS challenge CNAME records, platform subdomain and cluster suffix, SSL, HTTPS redirect and HTTP/2. With write mode enabled, external host changes, platform subdomain set/replace/clear and supported ingress settings are staged and reviewed as one diff; saves use prepare/PUT/read-back verification and then trigger ingress reconciliation. DNS challenge record names and targets can be copied. The offline fixture supports domain edits and sample records without contacting the API.
- Registry is available in live and mock modes. It lists registries and images first, then loads manifests when an image is opened. Manifests sharing tags appear once with all tag names together; untagged manifests show a shortened digest, while details show the full digest and image reference. With `--allow-writes`, `d` deletes an image or manifest after typing `delete`; `t` selects one tag to remove from a manifest while preserving the manifest. Mock deletes update only the in-memory fixture view. No registry creation endpoint is known in the current API map.
- MCP classifies `tui` as blocked, including when writes are enabled.

## Remaining for release 1A

- **1A-C1 through 1A-C5 implementation is complete.** C1 covers keyboard/style consistency and navigation. C2 covers request lifecycle and stale-result rejection. C3 covers typed Summary semantics and API-shaped fields. C4 covers terminal lifecycle, resize-state preservation, and long-session auth. C5 restricts writes to confirmed Restart/Delete, verifies mock isolation and the MCP block, and reconciles the docs. Release 1A still needs final interactive mock acceptance at minimum, normal, and wide terminal sizes, plus an authorized live read-only check if credentials are available.
- Live credential renewal and destructive live actions were not exercised. The mock was exercised in a PTY for normal quit and Ctrl+C; interactive PTY resize was unavailable.
